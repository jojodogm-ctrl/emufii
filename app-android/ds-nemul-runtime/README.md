# Runtime SILVER embarqué

Ce module embarque le vrai `libmpdsprobe.so` arm64 du NEmul public `41f251bf`. Le moteur est copié sans modification depuis l’APK référencé dans `upstream-pins.json`. La nouvelle bibliothèque JNI ne fait que résoudre ses exports C et adapter entrées, audio et écrans au frontend Emufii.

`DsNemulRuntime.open(context, NemulRoundRequest(...))` accepte une admission fraîche obtenue par le coordinateur authentifié, une ROM locale et son SHA256 attendu. Le fichier est copié et vérifié avant le boot. Chaque participant doit déjà disposer dans sa bibliothèque Emufii d’une ROM locale dont les octets ont le même SHA256 que ceux de l’hôte, région, révision et patch compris. Cette intégration ne fournit pas de distribution automatique de ROM pour SILVER. Le module n’accepte aucun deep-link externe, et ne tire ni clé ni adresse de relais d’une invitation.

SILVER configure `MPDS_NCON=N` et `MPDS_NOSTATE=1` : chaque appareil fait tourner réellement N consoles, pour 2 à 4 joueurs. Tous démarrent le même jeu en DirectBoot et chaque participant pilote son siège. Aucune table d’offset HLE ou savestate de Mario Party ne se trouve dans ce module. Le support général du moteur ne garantit pas qu’un jeu donné possède un mode local compatible. Les pseudos de firmware restent P1…PN pour un boot déterministe ; un futur profil personnalisé doit fournir le même roster complet à tous les appareils.

Le moteur ne connaît que `127.0.0.1:port`. `SilverUdpProxy` enveloppe ses datagrammes dans `emufii-silver-udp-v1` : header EDSW de 32 octets, AES-256-GCM, HKDF-SHA256, clés distinctes c2s/s2c, compteurs et fenêtre anti-replay de 128 paquets qui tolère les réordonnancements UDP. Les structures et tailles natives sont vérifiées avant remise au moteur ; les chunks de snapshot tronqués ou dont la longueur dépasse le stride sont rejetés. Le relais externe est une IPv4 numérique issue de la configuration du coordinateur. Les capacités par siège vivent uniquement en mémoire. Chaque admission est consommée une seule fois ; une reconnexion exige une nouvelle capacité pour éviter de réutiliser un nonce. Le relais serveur doit implémenter exactement le même format (`integrations/ds-private`).

Le service non exporté `:ds_silver_round` possède toutes les consoles et est détruit à la fermeture. `DsNemulRuntime.requestClose()` passe par l’Activity même si le lancement est encore en attente. L’APK principal attend la mort du Binder avant de libérer `activeStateFlow`; les callbacks d’une ancienne partie ne peuvent pas libérer une nouvelle partie. La shim ne lance pas le shutdown du core pendant son initialisation ; le processus jetable est détruit à une échéance fixe si le démarrage attend encore un autre siège. L’affichage passe par une mémoire partagée privée ; audio 32823 Hz, boutons DS, écran tactile, clavier/manette et micro opt-in sont présents. La perte de focus relâche les touches et coupe le micro ; un micro occupé ne coupe pas le son du jeu. Emufii doit réserver un seul runtime GOLD ou SILVER actif à la fois.

Le build nécessite un NDK et CMake 3.22.1 pour la seule shim ; il ne recompile pas les moteurs. `libc++_shared.so` est byte-identique au fichier du module GOLD. Le packaging racine peut conserver un seul exemplaire après vérification des deux SHA256. Aucune fonctionnalité n’est attestée sur un appareil par la présence de la bibliothèque ou par les tests unitaires.
